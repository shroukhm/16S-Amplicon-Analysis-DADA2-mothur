# DADA2 vs. mothur: Workflow Comparison

## Overview

This section compares two commonly used approaches for **16S rRNA amplicon sequencing analysis**:

* **DADA2**
* **mothur**

The comparison is based on the workflows explored during my **Research Internship at Nile University**.

The main goal is to understand how the two workflows process 16S rRNA data, how they generate microbial features, and how their different approaches may affect downstream analysis.

This comparison also provides a foundation for the **bioinformatics benchmarking** work being explored during the internship.

## Why Compare DADA2 and mothur?

DADA2 and mothur are both widely used for microbial community analysis, but they follow different approaches for processing amplicon sequencing data.

The most important conceptual difference is how they define the microbial features used for downstream analysis:

* **DADA2 → ASVs (Amplicon Sequence Variants)**
* **mothur → OTUs (Operational Taxonomic Units)**

Understanding this difference is important when comparing results generated by different bioinformatics workflows.

## ASVs vs. OTUs

### DADA2: Amplicon Sequence Variants

DADA2 uses a sequencing error model to distinguish biological sequence variation from sequencing errors.

The resulting features are **Amplicon Sequence Variants (ASVs)**.

ASVs represent exact inferred biological sequences after accounting for sequencing errors.

### mothur: Operational Taxonomic Units

Traditional mothur workflows can cluster sequences into **Operational Taxonomic Units (OTUs)** according to a sequence similarity threshold.

In the workflow explored here, a 3% distance threshold is used, corresponding to approximately **97% sequence similarity**.

The resulting OTUs therefore represent groups of sequences rather than individual exact sequence variants.

### Important Difference

ASVs and OTUs are **not directly equivalent features**.

An ASV represents an inferred exact sequence variant, while an OTU represents a cluster of sequences defined by a similarity criterion.

Therefore, comparing the number or abundance of ASVs and OTUs directly without considering their different definitions can be misleading.

## Comparison of Main Processing Steps

### 1. Quality Control

Both workflows perform quality control, but they approach the process differently.

**DADA2** uses functions such as:

```r
plotQualityProfile()
filterAndTrim()
```

to inspect read quality and apply filtering parameters.

**mothur** uses commands such as:

```text
make.contigs
summary.seqs
screen.seqs
```

to assemble reads and remove sequences that do not meet quality requirements.

---

### 2. Error Reduction

DADA2 explicitly learns sequencing error rates using:

```r
learnErrors()
```

and uses these error models during ASV inference.

mothur uses several preprocessing steps, including:

```text
unique.seqs
pre.cluster
chimera.vsearch
```

to reduce redundancy and sequencing/PCR artifacts before OTU generation.

---

### 3. Feature Generation

This is the main difference between the two approaches.

**DADA2:**

```text
Sequences
    ↓
Error modeling
    ↓
Denoising
    ↓
ASVs
```

**mothur:**

```text
Sequences
    ↓
Preprocessing
    ↓
Sequence distances
    ↓
Clustering
    ↓
OTUs
```

## Strengths of Each Approach

### DADA2

* Produces ASVs with exact sequence resolution
* Uses an explicit sequencing error model
* Avoids choosing a traditional OTU similarity threshold
* Provides high-resolution sequence features
* Integrates well with downstream R-based analysis

### mothur

* Provides a comprehensive workflow for microbial community analysis
* Includes many tools for sequence processing and analysis
* Supports traditional OTU-based analysis
* Provides extensive commands for microbial community analysis
* Offers an established and well-documented MiSeq SOP

---

## Similarities

Although their feature-generation strategies differ, both workflows include many common analysis stages:

1. Quality assessment
2. Read processing
3. Error/artefact reduction
4. Chimera removal
5. Taxonomic assignment
6. Feature table generation
7. Downstream microbial community analysis

Both workflows can therefore be used to analyze 16S rRNA amplicon sequencing data, while producing features with different definitions.

## Key Takeaways

* DADA2 and mothur can both be used for 16S rRNA amplicon analysis.
* DADA2 uses an **ASV-based approach**.
* Traditional mothur workflows can use an **OTU-based approach**.
* ASVs and OTUs have different biological definitions.
* DADA2 explicitly models sequencing errors during ASV inference.
* mothur uses a sequence processing and clustering workflow to generate OTUs.
* The choice of workflow can influence the resulting feature table and downstream analysis.
* Understanding these differences is important for meaningful **bioinformatics benchmarking**.
